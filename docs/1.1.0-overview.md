# jflux 1.1.0 implementation notes

## Scope

jflux 1.1.0 is being developed package by package. The goals are lower allocation
overhead, predictable memory use, simpler public APIs, and smaller runtime artifacts
where the package split allows it.

The current artifact split is retained for compatibility:

- `jflux-${version}-core.jar` for general utilities
- `jflux-${version}-db.jar` for database support
- `jflux-${version}-http.jar` for HTTP/API support
- `jflux-meridiandb-${version}.jar` and the full shaded jar for existing consumers

Downstream projects currently reference 1.0.6 artifacts. Those references should be
migrated only after each package change has passed the jflux tests and a consumer
compatibility build.

## Consumer inventory

Projects under `~/STRATO` that currently use jflux are:

| Project | Integration | Main jflux areas used |
| --- | --- | --- |
| `cxnfs` | local core jar | `sys` |
| `fortrow-api-server` | Maven dependency | `http` |
| `fortrow-cli` | Maven dependency | `crypto`, `encoding`, `http`, `sys` |
| `fortrow-rep` | Maven dependency | `http` |
| `liam` | local HTTP jar | `http`, `json` |
| LinkDB/MeridianDB modules | local core/full jars | `cloud`, `console`, `crypto`, `db`, `encoding`, `files`, `http`, `ssl`, and supporting utilities |
| `pariwall` | Maven dependency | no direct jflux imports found in source at review time |
| `puddles` | local HTTP jar | `crypto`, `db`, `encoding`, `http` |
| `time2rest` | local HTTP jar | `crypto`, `encoding`, `http`, `output.json` |

Cloud remains in the compatibility inventory but is not a required early package
target. It brings large provider SDK dependencies and should be handled separately
from the small core utility packages.

## Package order

The initial order is based on consumer reach and ability to validate behavior without
changing a protocol or storage format:

1. `encoding` (completed)
2. `crypto` (adapter and PQC foundation completed)
3. `files` (completed), `exceptions` (completed), `sys`, and `shell`
4. `threading` (completed) and `sockets` (completed)
5. `todash`, `json`, `output`, and `csv`
6. `db`
7. `http`
8. optional/provider packages such as `cloud`, email, SSL, and integrations

Each package change must retain existing public entry points where practical, add
focused tests for edge cases, and update the package documentation in this directory.

## Cross-package exception migration

The completed `encoding`, `crypto`, and `files` work now uses
`com.fortrow.jflux.exceptions.ExceptionHandling` at legacy error boundaries. This
centralizes automatic logging and optional reporting while preserving existing
nullable results, sentinel byte arrays, and runtime exception contracts where
downstream STRATO applications depend on them. New package work must use the
jflux exception types directly or pass compatibility failures through this bridge.

The `com.fortrow.jflux.mcp` package now provides a JSON-RPC MCP server/client pair
and the MCP exception reporter. It supports stdio and JDK HTTP transport adapters
without adding an MCP SDK dependency to the core artifact.

The `sys` and `shell` milestone now provides structured, bounded command
execution; cross-platform package auditing and installation; Java metadata
helpers; and language-neutral Git/wget source installer composition. Legacy shell
entry points delegate to the shared runner.

The `threading` milestone now uses virtual-thread-backed lifecycle helpers,
bounded executor queues, explicit worker termination, and consistent exception
reporting for background failures.

The `sockets` milestone now uses Java 21+ virtual threads for accept/session
work, UTF-8 line framing, idempotent close callbacks, lifecycle observation, and
blocking session reads without polling delays.

The `todash` milestone modernizes the historical `__` facade with reusable
patterns, null-safe/value-aware helpers, lower-allocation console and string
operations, and a focused Lodash-style collection API without adding a runtime
dependency.

The `json` milestone now uses JSON-Simple for the default parse and compact
serialization path, caches Gson only for explicit typed conversion and pretty
formatting, restores object/array compatibility helpers, and keeps the legacy
`com.fortrow.jflux.json.JSON` namespace as a delegating facade. See
[`json.md`](json.md) for the strict and legacy API behaviors.

The `http` milestone is now applying the redefined exception model across REST
and encrypted API boundaries. It adds reportable `APIException` failures,
bounded request-body reads, strict JSON/required-parameter validation, safer
timestamp/header handling, and explicit HTTP 413 responses for oversized bodies.
See [`http.md`](http.md) for the current request and client resource behavior.

The `ssl` milestone now validates certificate inputs, builds Java TLS contexts
without swallowed failures, supports PKCS#8 PEM key material and certificate
chains, and uses bounded argument-list OpenSSL execution for self-signed and
private-CA certificates. See [`ssl.md`](ssl.md) for supported formats and
compatibility behavior.

The `websockets` milestone now provides a reusable Java-WebSocket transport
with matching server/client lifecycle callbacks, per-connection state, text and
binary frame support, bounded message sizes, and reportable handler failures.
It intentionally leaves authentication and REST/encrypted message routing to
injected handlers. See
[`websockets.md`](websockets.md) for the transport contract.

The `output` milestone keeps JSON in its established namespace, adds practical
JSON/XML conversion, and moves the secure XML loader to `com.fortrow.jflux.xml`
with a deprecated compatibility wrapper. See [`output.md`](output.md).

The `csv` milestone is an independent `com.fortrow.jflux.csv` package with
streaming FastCSV factories and deterministic small-file helpers. See
[`csv.md`](csv.md).

The `db` milestone keeps its existing fluent syntax while adding validated
SQLite PRAGMA support, batch inserts, map-based insert/update overloads,
`DISTINCT`, `HAVING`, `LIMIT/OFFSET`, `RETURNING`, and conflict-ignore inserts.
JDBC statements and result sets are now closed deterministically, and `Db` and
`DbConnection` can be used with try-with-resources. See [`db.md`](db.md).

The `runtime` milestone now provides a JFlux-native dynamic execution library
adapted from the Fortrow CLI runtime design. It supports immutable execution
requests, virtual-thread timeouts, bounded in-memory JAR loading, encrypted
AES-GCM packages, ServiceLoader-style function discovery, source precedence,
and explicit package cleanup. See [`runtime.md`](runtime.md).

The `yaml` milestone now reuses SnakeYAML settings and the JSON-Simple-first JSON
facade, adds bounded stream/path parsing and multiple-document support, avoids
the extra `FileObject` byte-buffer copy, and keeps typed Gson conversion cached
for compatibility. See [`yaml.md`](yaml.md).

The `console` and `stdout` milestone now provides a structured JSON terminal
editor with arrow-key navigation, raw Unix TTY restoration, deterministic
stream-mode editing, and object/array insertion shortcuts. `Terminal` adds
ANSI-aware prompts, confirmations, menus, styling, and cursor helpers, while
`ProgressTaskList` moves to stdout with thread-safe task updates and a
deprecated console compatibility facade. See [`console.md`](console.md) and
[`stdout.md`](stdout.md).

The `jni` milestone now provides normalized OS/architecture identifiers,
bounded classpath native-library extraction and loading, JNI header/source
template generation, and an argument-list native build helper that uses the
shared shell runner. See [`jni.md`](jni.md).

The `email` milestone now provides a dependency-free SMTP transport with
validated STARTTLS/implicit TLS, authenticated SMTP, MIME text/HTML messages,
streamed attachments, virtual-thread sends, and Gmail/Outlook provider presets.
The exception email reporter reuses this transport without recursive reporting.
See [`email.md`](email.md).
