# JFlux 1.2.0

The encrypted API can select ML-KEM-512, ML-KEM-768, or ML-KEM-1024 for its rotating key envelopes. RSA-2048 remains the default for existing applications. See [HTTP](http.md) for configuration and [crypto](crypto.md) for the envelope implementation.

New clients generate their private key locally for both RSA and ML-KEM, sending only their public key during initialization or resume. Both peers must select the same suite. Old RSA bootstrap formats remain supported for compatibility. Session controls, request authentication, and transports share the same protocol implementation.

Maven artifacts and MCP server version metadata report `1.2.0`. The HTTP shaded
artifact now bundles Bouncy Castle so its post-quantum option is ready to use.

## Validation

Validated on Java 23 with all 177 tests passing. Integration tests cover every
suite over HTTP and WebSocket, encrypted error responses, key cleanup on close,
fresh keys on resume, downgrade rejection without consuming a valid resume token,
and the legacy RSA bootstrap. A separate smoke check executes all four suites
using only the packaged HTTP JAR, including its bundled ML-KEM provider.

Built artifacts are in `target/`: `jflux-1.2.0.jar`, `jflux-1.2.0-http.jar`,
`jflux-1.2.0-core.jar`, `jflux-1.2.0-db.jar`, and `jflux-meridiandb-1.2.0.jar`.
